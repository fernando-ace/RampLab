# Canonical package schema 1.0

The artifact is UTF-8 JSON with a final newline and sorted object keys. Top-level fields: `schema_version` (currently `1.0`), `airport`, `dataset`, `sources`, `flights`, `aircraft`, `gates`, `equipment`, `turnaround_requirements`, `disruptions`, and `validation`. Unsupported schema versions are rejected by the source manifest loader; consumers should reject unknown major versions.

`airport` preserves supplied airport metadata: required `airport_id` and IANA `timezone`; optional `name`, `iata`, `icao`, descriptions. `dataset` contains stable `dataset_id` and `description`. `sources` is ordered by relative filename; each entry contains filename, `csv`/`json` type, raw-file SHA-256, record count, accepted count, and rejected count. Source paths are relative.

Each entity collection is a sorted array of source field objects. Required flight fields: unique `flight_id`, `operation` (`arrival`/`departure`), UTC `scheduled_time`, and `aircraft_id`; optional flight number, callsign, airline, estimated/actual time, gate, origin, destination, status, and explicit related-flight ID are retained. Optional `occupancy_start`/`occupancy_end` enables conservative gate overlap checks. Aircraft requires unique ID and type; registration, model, ICAO type, category, dimensions, and source units may be supplied. Dimensions normalize to meters (`m`) from meters, feet, or inches. Gate requires unique gate ID; terminal/concourse/status/availability/compatible class/location/remote marker are optional. Equipment requires unique ID, supported type (`tug`, `baggage_vehicle`, `fuel_vehicle`, `catering_vehicle`, `service_cart`, `ground_service_vehicle`) and status. Turnaround requirements use unique `requirement_id`, service type, nonnegative `duration_minutes`, and optional flight/aircraft/equipment references, earliest start, dependency, priority, and status. Disruptions use unique ID, type, start time, and optional end/duration/reason and target IDs.

Times are UTC ISO-8601 strings ending `Z`; naive input times use `airport.timezone`. Durations are minutes and must be nonnegative. IDs are trimmed but case-preserving. References from flights to aircraft/gates, services to flights/aircraft/equipment, and supported disruption targets must resolve. `validation` contains status, counts, and ordered structured findings with stable code, severity, source, record, field, value, and message.

Missing optional values are omitted. No generation time is emitted. Deterministic ordering and serialization guarantee byte stability for the same manifest and raw source files. Provenance hashes differ for equivalent CSV and JSON source bytes.

## Airport operational geometry extension

The KAUO geometry dataset is a separate spatial artifact (`kauo_operational_geometry.json`) in this subsystem; it does not change tabular package schema 1.0. Every active or rejected geometry record includes a stable `geometry_id`, feature/geometry type, coordinates and CRS, `source_id`, `source_type`, nullable `source_date`, `capture_method`, `classification` (`AUTHORITATIVE`, `SOURCE_DERIVED`, `APPROXIMATE`, `SYNTHETIC`), matching boolean `authoritative`, nullable `accuracy_m`, source-confidence score in `[0,1]`, `simulation_approved`, and notes. `accuracy_m: null` means the source did not publish accuracy. Source confidence describes the source attribution and classification; it is not a replacement for accuracy.

Operational graph nodes/edges and relationships carry source provenance and explicit simulation approval. Route/clearance evidence is unknown unless it includes a source, method, required/measured clearance, confidence, and explicit approval. Geometry that is not suitable for operations can remain in `rejected_features`; authoritative mode inspects the active `features` collection and rejects approximate or synthetic records. The KAUO readiness audit is fail-closed and does not infer missing infrastructure.

Run `python -m tools.airport_data_ingestion.kauo_geometry --authoritative-mode` to validate the raw FAA AUO extract against its anchor snapshot, regenerate the deterministic geometry dataset, readiness report, and SVG comparison. Add `--require-ready` to return exit code 2 when the gate blocks scenario execution. The Goal45 schema, audit, and deterministic behaviors are covered by `test_kauo_geometry.py`.
